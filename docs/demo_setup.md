# RECLAIM — Razorpay Live Demo & Test-Mode Webhook Setup Guide

This guide details how to run the end-to-end live demonstration of **RECLAIM** using Razorpay test-mode credentials and webhooks.

---

## 1. Prerequisites

1. **Razorpay Test Account**:
   - Access the [Razorpay Dashboard](https://dashboard.razorpay.com/) in **Test Mode**.
   - Navigate to **Settings → API Keys** and generate a `Key ID` and `Key Secret`.
   - Copy them into your `.env` file:
     ```env
     RAZORPAY_KEY_ID=rzp_test_...
     RAZORPAY_KEY_SECRET=...
     RAZORPAY_WEBHOOK_SECRET=your_test_webhook_secret
     ```

2. **Python Environment**:
   - Ensure your virtual environment is active and dependencies are installed:
     ```bash
     python -m alembic upgrade head
     ```

---

## 2. Option A: Automated Live Demo Script (No Tunnel Needed)

For local evaluation, judge walkthroughs, and automated CI/CD verification, run the automated test-mode demo script:

```bash
# 1. Start the RECLAIM server in one terminal
python main.py

# 2. Run the end-to-end demo script in a second terminal
python scripts/demo_razorpay_live.py
```

### What the Demo Script Does:
1. **API Check**: Verifies that the RECLAIM FastAPI server and `/test/simulate-webhook` endpoints are live.
2. **Razorpay Test Link Generation**: Uses `razorpay.Client` to generate a real Razorpay test-mode Payment Link (no real money moves).
3. **Failure Ingestion**: Dispatches a realistic `payment.failed` event (`BAD_REQUEST_ERROR` / `INSUFFICIENT_FUNDS`) to the live webhook router.
4. **Full Recovery Loop Execution**:
   - HMAC signature verification and payload idempotency deduplication.
   - Normalized event ingestion into the database.
   - Failure cause diagnosis with confidence scoring.
   - Deterministic policy engine evaluation (enforcing contact fatigue, ROI gate, discount ceiling, 0 violations).
   - Recovery action dispatch (simulated SMS/WhatsApp nudge with payment link).
5. **Customer Recovery Simulation**: Dispatches `payment.captured` to close the recovery loop and update customer `RecoveryMemory`.
6. **Live Audit Verification**: Queries the database and prints the chronological state transitions and audit logs.

## 3. Option B: Real Razorpay Webhook Tunneling (via Ngrok)

To receive real webhooks from the Razorpay Test Dashboard when testing with dummy cards:

### Step 1: Start Ngrok Tunnel
```bash
ngrok http 8000
```
Copy the public HTTPS forwarding URL (e.g. `https://abcd-1234.ngrok-free.app`).

### Step 2: Configure Razorpay Dashboard Webhook
1. In the Razorpay Dashboard, switch to **Test Mode**.
2. Navigate to **Settings → Webhooks → Add New Webhook**.
3. **Webhook URL**: `https://abcd-1234.ngrok-free.app/webhooks/razorpay`
4. **Secret**: Set a secret (matching `RAZORPAY_WEBHOOK_SECRET` in `.env`).
5. **Active Events**:
   - `payment.failed`
   - `payment.captured`
   - `order.paid`
6. Save the webhook.

### Step 3: Trigger a Test Payment Failure
1. Use the Payment Link generated by RECLAIM or Razorpay checkout.
2. Enter standard test card details:
   - **Card Number**: `4000 0000 0000 0002` (Simulates failure: Insufficient Funds) or `4000 0000 0000 0005` (Invalid OTP).
   - **Expiry**: Any future date (e.g., `12/28`).
   - **CVV**: `123`.
3. Submit payment — Razorpay will emit a live `payment.failed` webhook to your ngrok URL.
4. Watch the RECLAIM terminal execute diagnosis → deterministic policy verification → recovery dispatch in real time.
5. Inspect the result in the **Live Dashboard**: `http://localhost:8000/dashboard`.
